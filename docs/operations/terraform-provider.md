# Terraform and OpenTofu provider

The provider under `providers/terraform` manages AMESH 0.2 configuration through the public API. It
serves plugin protocol v5 and exposes matching resources and data sources for flows, namespace
bundles, namespace files, key-values, dashboards, apps, users, groups, roles, bindings, service
accounts, tenants, worker-group policy sets and plugin-policy rules.

## Configure

Prefer environment-backed credentials:

```console
export AMESH_ENDPOINT=https://amesh.example.test
export AMESH_TOKEN='...'
export AMESH_TENANT=default
```

Declare `source = "amesh/amesh"` in `required_providers`. For an unpublished local build, install the
binary with a Terraform/OpenTofu development override or filesystem mirror. The generated provider,
resource and data-source references are in `providers/terraform/docs`.

Resources accept a `key`, optional `namespace` and JSON/YAML `document`. Formatting and mapping-key
order do not produce a plan. Refresh calculates `remote_digest`; an out-of-band caller-owned field
changes `document`, sets `drifted`, and produces an update plan. Server-generated IDs, ETags,
revisions, timestamps and safe defaults remain computed and do not overwrite configuration.

For write-only values, set `secret_environment` to the name of an environment variable and put
`${AMESH_SECRET}` in the document. The provider resolves the placeholder only in request memory,
recursively redacts responses and does not persist the plaintext value. Treat Terraform state as
sensitive because ordinary caller-supplied document values remain in state.

## Import and lifecycle

Import IDs use:

```text
kind|tenant|namespace|key
kind|tenant|namespace|key|server_id
```

Use the fifth part for resources whose API identity is generated by the server. URL-encode literal
pipe characters inside a part. Import refreshes the redacted remote document, removes server-only and
empty default fields, and then participates in normal plan/apply drift handling.

Namespace bundles, apps, roles, service accounts and worker-group policy sets are retained when their
Terraform state is removed because AMESH owns their history or they may be shared. Other resources
invoke native delete endpoints. Binding and service-account documents are immutable and require
replacement; tenant policy updates preserve the tenant slug and server identity.

## Release

The compatibility matrix is `providers/terraform/compatibility.json`. A platform version tag runs
GoReleaser after the main release job, builds the six qualified OS/architecture archives, includes the
protocol manifest in `SHA256SUMS`, signs that checksum file with the operator's RSA/DSA GPG key and
uploads the assets to the GitHub release. The Terraform Registry requires a public repository and the
matching public signing key. Those account-bound publication steps are release-operator actions; the
build matrix, checksum layout and signature operation are locally reproducible.
