# AMESH differentiators

The product owner accepted all of the following as in-scope differentiators.

## One fully open distribution

Identity, governance, audit, multi-tenancy, worker isolation, distributed operation, policy and administration are implemented in the public AGPL source tree rather than separated behind a closed edition.

## Isolated, language-neutral plugins

Third-party plugins run outside control-plane processes with explicit capabilities, signed packages and SDKs in Java, Python and TypeScript. Migration tooling translates compatible configuration and generates evidence rather than silently loading arbitrary code.

## Deterministic simulation

Users can preview expanded task graphs, branch decisions, policy outcomes, capacity assumptions and declared side-effect boundaries before execution. Simulation results identify uncertainty rather than pretending external systems are deterministic.

## Policy as code

Open, testable admission policy governs authoring, promotion, execution, runners, images, plugins, agent tools, secrets, egress, cost and human approval requirements.

## Evidence-backed agentic assistance

AI may propose workflows, repairs and operational explanations, but every action is bounded by permissions and supported by validation, simulation, tests and platform records.

## First-class agent mesh runtime

AMESH models agents, messages, hand-offs, memory scopes, checkpoints, provider routing, tool calls, budgets, evaluations and approvals as durable governed resources within the same execution state machine as ordinary workflow tasks.

## AI-native engineering factory

The project itself can be developed by elastic AI engineering teams while preserving clean-room separation, isolated worktrees, independent review, reproducible gates, provenance and explicit release authority.

## Explicit semantic honesty

At-least-once delivery, idempotency, fencing and external side-effect limitations are documented and tested rather than hidden behind an “exactly once” slogan.
